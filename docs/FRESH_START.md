Работ, ответов и уведомлений в базе не было. После удаления счётчики этих таблиц тоже нули.

Скрипт: `python -m scripts.reset_prototype --yes` при `ENV=dev`, `STIMUL_ALLOW_RESET=1` и `STIMUL_RESET_DATABASE=stimul`. Он удаляет строки в порядке внешних ключей. `TRUNCATE CASCADE` по всей схеме не используется. Класс, предмет и школа из списка удаления исключены.

## 2. Какая база

Живой контур `stimyl.online` это одно приложение Timeweb:

| | |
| --- | --- |
| Приложение | «Копия Stimyl», id `279257`, ветка `feature/accounts` |
| Адреса | `stimyl.online`, `f4dd-dev-stimyl-1cea.twc1.net` |
| Приложение `277859` | в аккаунте отсутствует, API отвечает `404` |
| Кластер | PostgreSQL 16, id `4226125`, адрес `193.188.23.51:5432` |
| База приложения | `stimul` |

На кластере есть ещё `default_db` и `postgres`. Пользователь `stimul` к ним подключиться не может. FastAPI и worker запускаются одним `docker/entrypoint.sh` и читают один `DATABASE_URL`. Отдельного Redis нет: очередь бота лежит в таблице `jobs`, она очищена.

Локальный `.env` указывает на SQLite `.local/stimul.db`. Этот файл не цель и не изменялся.

`ENV`, `SEED_DEMO` и `FIRST_TEACHER_BOOTSTRAP` в окружении `279257` не заданы. Код принимает это как `ENV=dev`, `SEED_DEMO=false`, `FIRST_TEACHER_BOOTSTRAP=false`. Это не `ENV=prod`.

Резервная копия до удаления: `.local/backups/stimul-20261103-093851.dump`, 110709 байт, формат `pg_dump -Fc`. Каталог `.local` не входит в git. У файла нет наследования прав, доступ есть только у текущей учётной записи Windows. `pg_restore --list` архив прочитал. В чат и в git его не класть.

## 4. Как проверить, что база пустая

Команды ниже запускать с `DATABASE_URL` тестовой PostgreSQL, не с SQLite из `.env`. Пароль в чат не копировать.

```text
python -m app.admin users
python -m app.admin class
python -m app.admin claims
```

Ожидание сразу после очистки: `users` пустой, в `class` нет ответственного и нет учеников, `claims` пустой.

Тот же смысл в SQL:

SELECT count(*) AS users FROM users;

SELECT count(*) AS phones FROM users WHERE phone_hash IS NOT NULL;

## 5. Как запустить FastAPI и worker

На Timeweb процесс уже запущен приложением `279257`. Этот проход его не перезапускал. Воркер жив: `worker_heartbeat` обновляется, а `jobs` пуст, поэтому старые апдейты он разобрать не может.

Локально, из корня репозитория, в окружении процесса, не в файле `.env`:

```text
ENV=dev
SEED_DEMO=false
FIRST_TEACHER_BOOTSTRAP=true
DATABASE_URL=postgresql+asyncpg://stimul:<пароль>@193.188.23.51:5432/stimul?ssl=require
```

Пароль брать из панели Timeweb или из `.local/db-password.txt`. Затем:

```text
python -m app.db.migrate
python -m app.db.seed
python -m app.worker
uvicorn main:app --host 127.0.0.1 --port 8000
```

Локальный worker с тем же `MAX_TOKEN`, что у `stimyl.online`, перехватит вебхук. Для проверки живого бота достаточно уже работающего приложения `279257`. Второй процесс с `MAX_WEBHOOK_URL` не запускать.

## 6. Как включить тестовый bootstrap

Сейчас флаг в базе `open`, но приложение его не применяет: `FIRST_TEACHER_BOOTSTRAP` не задан и по умолчанию `false`. Пока так, первый подтверждённый номер станет учеником с заявкой, а не учителем.

Включить только на `279257`, до первого нажатия «Поделиться номером»:

```text
ENV=dev
FIRST_TEACHER_BOOTSTRAP=true
SEED_DEMO=false
```

`ENV` можно не писать, пустое значение уже считается `dev`. Нельзя ставить `ENV=prod`: при `prod` код игнорирует bootstrap. Нельзя включать это на будущем боевом приложении.

`PATCH /api/v1/apps/279257` заменяет всю карту переменных и сразу деплоит. Этот проход Timeweb не трогал. Как собрать карту заново, написано в `docs/TIMEWEB.md`.

## 7. Как зарегистрироваться первым

1. Открыть в MAX бота `ideya_fiks_101_bot` со своего аккаунта.
2. Нажать «Согласен». Согласие без номера роль учителя не даёт.
3. Нажать «Поделиться номером». Номер текстом и пересланная карточка не принимаются.
4. Сервер проверяет HMAC контакта. Только после этого, если bootstrap включён и флаг `open`, этот аккаунт становится учителем-администратором класса `8Б` по математике.
5. Следующий подтверждённый номер получает заявку ученика со статусом `pending`.

Пока `FIRST_TEACHER_BOOTSTRAP` выключен, шаг 4 создаёт ученика, а не учителя. Сначала включить флаг, потом подтверждать номер.

## 8. Как проверить, что вы учитель-администратор

Бот отвечает: «Ты учитель-администратор. Класс 8Б, предмет Математика.»

```text
python -m app.admin users
python -m app.admin class
```

В `users` одна строка: роль `teacher`, статус `active`, управление `да`. В `class` ответственным назван этот человек. `prototype_bootstrap` становится `consumed`. Второго администратора bootstrap больше не назначает. Полный номер команда не печатает. Маска видна в SQL ниже.

```sql
SELECT role, status, can_manage_school, phone_mask
FROM users
WHERE deleted_at IS NULL;

SELECT value FROM runtime_flags WHERE key = 'prototype_bootstrap';
```

## 9. Как принимать учеников

Следующий человек проходит то же согласие и кнопку «Поделиться номером». Бот пишет, что заявка в 8Б ждёт подтверждения.

Учитель в чате пишет «заявки» или нажимает кнопку заявки. «Принять» ставит ученику `active`. Отклонение оставляет заявку закрытой и пишет ученику.

В кабинете те же заявки у человека с `can_manage_school`. Команда `python -m app.admin claims` показывает очередь, людей она не назначает.

Код класса `8Б` сейчас `8AFC616C`. Для этого прототипа он не обязателен: заявка создаётся подтверждением номера. Код виден в `python -m app.admin schools`.
