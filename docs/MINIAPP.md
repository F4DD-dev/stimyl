# Мини-приложение и бот MAX

Как сейчас устроен вход. Это описание кода на ветке `feature/accounts`, не план новых фич. Продуктовые инварианты — в `AGENTS.md`. Учётные записи — в `docs/ACCOUNTS.md`.

Живой контур: приложение Timeweb «Копия Stimyl», id `279257`, ветка `feature/accounts`, адрес `https://stimyl.online`. Бот `ideya_fiks_101_bot`, его `user_id` `387830563`. Токен только в `MAX_TOKEN`. Вебхук: `https://stimyl.online/webhook`. `GET` окружения Timeweb маскирует секреты, а `PATCH` заменяет всю карту: как собрать её заново, написано в `docs/TIMEWEB.md`.

Документация MAX, с которой сверен этот путь:

- кнопка: [NewMessageBody](https://dev.max.ru/docs-api/objects/NewMessageBody/), пример `open_app`
- мост: [MAX Bridge](https://dev.max.ru/docs/webapps/bridge)
- запуск и диплинк: [подключение мини-приложения](https://dev.max.ru/docs/webapps/introduction)
- скрипт моста: `https://st.max.ru/js/max-web-app.js`
- клиент `@maxhub/max-bot-api`: `openApp(text, webApp, contactId, payload)`

## Два идентификатора

`user_id` из апдейта бота и `user.id` из `initData` мини-приложения **не считаются одним числом**, пока нет живой сверки. `ALLOW_ID_MATCH` выключен. Привязка мини-приложения — отдельная строка `auth_identities.provider = max_webapp`. Её создаёт одноразовый билет, а не сам факт открытия приложения.

## Кто что делает

```
MAX  --webhook-->  POST /webhook  --jobs-->  worker  --POST /messages-->  MAX
человек жмёт open_app
MAX открывает https://stimyl.online/...#WebAppData=...
страница  --POST /api/session-->  FastAPI  --cookie и token-->  страница
дальше страница ходит только в FastAPI, в PostgreSQL напрямую нет
```

Webhook только кладёт апдейт в очередь и отвечает 200. Сообщения шлёт воркер (`app/worker.py`). Имя бота и `contact_id` оба процесса берут из `GET /me` при старте (`app/main.py` `_learn_bot_name`, `app/worker.py` `serve`). Короткий тестовый токен в сеть не уходит.

## Кнопка, которая открывает кабинет

Кнопка типа `link` на `max.ru` открывает вкладку и билет в мини-приложение не приносит. Нужна `open_app`. Без `contact_id` MAX открывает приложение и выбрасывает `payload`. Без `payload` нечего класть в `start_param`.

```json
{
  "type": "open_app",
  "text": "Открыть кабинет",
  "web_app": "ideya_fiks_101_bot",
  "contact_id": 387830563,
  "payload": "<билет>"
}
```

- `web_app` — публичное имя бота, не URL и не текст кнопки.
- `contact_id` — `user_id` бота из `GET /me`, не id человека.
- `payload` — билет: `A–Z`, `a–z`, `0–9`, `_`, `-`, до 512 знаков. Иначе MAX молча его удаляет.

Сборка: `app/max_client/client.py` `_button`. Если `contact_id` ещё нет, кнопка не отправляется (`app/bot/gate.py`). В логе воркера при отправке есть `open_app contact_id=... payload=set`. Значение билета в лог не писать.

Билет — `secrets.token_urlsafe(32)`, в базе только хэш. Живёт 5 минут, один раз, не больше 5 выпусков в час. Старая кнопка в чате новый билет не получает.

Кто получает кнопку:

| Фраза или callback | Кому | Кнопка |
| --- | --- | --- |
| «Войти в кабинет», `web_login`, `open_cabinet` | учитель и администратор | «Открыть кабинет» |
| «Мой прогресс», `progress` | ученик | «Мой прогресс» |
| `/start` | никому билет не выдаёт | — |

Кнопка «Открыть» в шапке чата — это кнопка из настроек бота на business.max.ru. У неё нет нашего `payload`. Экран «открой кнопкой из чата» для неё правильный.

Диплинк с билетом, если понадобится ссылка: `https://max.ru/<бот>?startapp=<payload>`. Это не то же самое, что `?start=` (тот открывает только чат, лимит 128).

## Что страница читает при запуске

Мост кладёт подписанную строку в hash-параметр `WebAppData`, не в query `initData`. Скрипт моста в `app/web/index.html` подключён без `async`: модуль `app.js` должен стартовать после него.

`app/web/js/app.js` берёт `initData` так:

1. hash `WebAppData`
2. `window.WebApp.initData`
3. query `WebAppData` или `initData`
4. `sessionStorage.WebAppData` — запас моста, если hash уже заменили на `#/экран`

`start_param` берётся из `initDataUnsafe.start_param`, из самой строки `initData` и из `WebAppStartParam`. Подпись на клиенте не проверяется.

## Вход на сервере

`POST /api/session` с телом `{init_data, start_param}`.

1. `app/security/init_data.py` проверяет HMAC: ключ `HMAC_SHA256("WebAppData", MAX_TOKEN)`, затем подпись отсортированных пар `key=value`. Срок — час по `auth_date`. Отсюда `user.id` и `start_param`.
2. Подписанный `start_param` важнее поля из тела. Поле из тела принимается только если оно в алфавите билета и в подписи параметра нет.
3. Ищется `auth_identities(provider=max_webapp, external_id=user.id)`.
4. Нет строки и есть билет — `claim_webapp_ticket`: блокировка строки, проверка срока, запись `max_webapp` в той же транзакции, билет гасится. Чужой `user.id` на тот же билет не садится.
5. Нет привязки — **409** `Открой приложение кнопкой из чата с ботом.`
6. `blocked` или не `active` — **403**, это другой экран.
7. Успех — cookie `stimul_session` (`SameSite=Lax`, HttpOnly) и JSON `{role, csrf, token}`.

Окно MAX cookie не сохраняет. Следующий `GET /api/session` без токена даёт 401. Страница шлёт `Authorization: Bearer <token>` (`app/web/js/api.js`, ключ `sessionStorage` `stimul_session`). `user_from_cookie` принимает cookie или этот заголовок. Не убирать заголовок и не оставлять только cookie.

Лог `miniapp start_param=` пишет одно из `signed`, `hint`, `absent`. Рядом причина отказа: `unsigned`, `unlinked`, `blocked`, `pending`. Билет в лог не попадает.

Экран `unlinked` в `app.js` зашит фразой «Открой приложение кнопкой из чата с ботом» и на **409**, и на **401 внутри MAX**. 401 после успешного `POST /api/session` — это потеря сессии, а не потеря билета. Смотреть лог, не только экран.

«Вернуться в чат» вызывает `WebApp.openMaxLink("https://max.ru/<бот>")`. Метода `WebApp.close()` нет. Имя бота страница берёт из `data-bot`.

## Что человек делает в боте

Новый человек без активного зачисления и без строки `class_teachers` не попадает в тренировку. Живой прототип один: класс 8Б, математика. Город, школа и место в 5А в этот вход не входят.

1. «Согласен», затем кнопка «Поделиться номером».
2. Если включён тестовый первый вход и место ещё свободно, этот человек становится учителем-администратором. В production так не происходит.
3. Остальные получают заявку `pending`. Ответственному уходит сообщение в MAX.
4. Если ответственного нет, заявка остаётся, а бот прямо говорит, что принять её некому.
5. Учитель-администратор пишет «заявки» и жмёт «Принять» или «Отклонить».
6. Принятый получает сообщение в MAX и пишет `/start`.

Команды бота для учителя: «заявки», «ученики», «мой класс», «войти в кабинет». Как назначить первого ответственного, написано в `docs/ADMIN_GUIDE.md`.

## Кабинет после входа

Страницы: `/` (`data-entry=auto`), `/student`, `/cabinet` (`teacher`). Все отдают один `app/web/index.html`.

Роль в интерфейсе сравнивается строго с `teacher`. Роль `admin` туда не входит: API учителя требует роль `teacher`, API ученика — `student`. Администратор школы проходит вход и упирается в 403 на обоих наборах ручек. Это текущее поведение, не отдельный кабинет администратора.

Ученик читает только свой прогресс. Текст личного вопроса учителю не отдавать. Загрузка работ учителем (`POST /api/teacher/assignments`) ещё не сделана.

`?preview=student|teacher` рисует локальные данные и на сервер за ответами не ходит. `?ticket=` — вход по ссылке для браузера, не для кнопки `open_app`.

## Что проверять, если «кнопка снова не пускает»

1. В логе воркера на эту отправку есть `open_app contact_id=387830563 payload=set`. Нет `contact_id` — кнопка выпущена старым процессом или `GET /me` не удался.
2. На `POST /api/session` есть `miniapp start_param=signed` или `hint`. `absent` — в `WebAppData` параметра не было: шапка чата, старая кнопка или страница прочитала не тот hash.
3. Этот POST вернул 200, а следующий GET — 401: билет дошёл, сессия не удержалась. Проверить, что страница шлёт `Authorization: Bearer`.
4. POST 409 — привязки `max_webapp` нет и билет не подошёл (чужой, протух, уже использован).
5. POST 401 `unsigned` — `MAX_TOKEN` на сервере не тот, которым MAX подписал `initData`.

Закрытая панель держит старый JS. После выкладки человеку нужно закрыть её крестиком и нажать новую кнопку.
