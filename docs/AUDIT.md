# Аудит прототипа «Стимул»

Дата: 2026-10-30. Код не менялся. Этот файл — единственная правка этапа 0.

Сверка с новым ТЗ на мини-продакшн (пилот 8Б, математика, четыре темы) и со старым `docs/PLAN.md`. Контракт MAX сверен с `dev.max.ru/docs/webapps/bridge` (страница открылась) и с клиентской памяткой по Bot API от 2026-09-21. Страница `dev.max.ru/docs-api` в этот заход не открылась: где из-за этого нет уверенности, стоит TODO.

Тесты в этом проходе не запускались: в репозитории нет `.venv`, у системного Python 3.12.10 нет модуля `pytest`.

## 4. Состояние диалога

Оно в PostgreSQL, в таблице `sessions`. На апдейт читается последняя строка пользователя (`app/bot/service.py`, `_load_state`, строки 171–180) и туда же пишется обратно (`_save_state`, 221–229). После рестарта процесса занятие продолжается, если транзакция успела закоммититься. В памяти процесса диалог не хранится. Это не баг «состояние в RAM».

Рядом три настоящих дефекта хранения и доставки:

- Long polling записывает маркер до обработки пачки. Упавший апдейт больше не придёт (`app/bot/poll.py:34–37`).
- На одного пользователя нет блокировки. Два одновременных апдейта читают одну и ту же сессию (`app/bot/service.py:45–79`).
- Кнопка несёт только `действие` или `действие:id темы` (`app/bot/service.py:369`). Версии шага нет, устаревшая кнопка выполняет действие заново.

## 5. Что уже работает

Это закрывает фазы 0–4 старого плана, не новое ТЗ целиком.

- Сервис, Alembic, seed класса 8Б (учитель и четверо учеников с вымышленными id), четыре темы.
- Вебхук с постоянным сравнением секрета, long polling, сертификат Минцифры в httpx-клиенте, команда `/start`.
- Тренировка: тема → объяснение → пример → задание из банка → зачёт кодом. В ответе ученику нет эталона. `eval` нет.
- Личные реплики пишутся с `visibility=private`. Карта учителя их не сериализует. Чужой `user_id` в запросе прогресса игнорируется, отдаётся только владелец cookie (`tests/test_flow.py`).
- Статус считается кодом по всем попыткам темы. Пороги вынесены в настройки, старт 50% и 80%.
- Вход в мини-приложение: `initData`, HMAC от ключа `WebAppData`, свежесть `auth_date` (час), роль из БД. Кнопка «назад» в кабинете обрабатывается. Скрипт Bridge подключён.
- Черновик проверки учитель видит. Отправка в MAX честно отвечает 501. Генерация «по материалу» отказывается, пока фрагментов нет.
- Повторная доставка того же `mid` второй попытки не создаёт (`tests/test_flow.py`).

## 7. Баги

Ниже то, что код делает неверно относительно собственного сценария или нового ТЗ. Номера строк — на 2026-10-30.

### Данные и безопасность

1. Любой, кто написал боту, становится учеником 8Б и появляется на карте. `app/bot/service.py:140–147`. Для публичного бота это смешивает чужих людей с классом.
2. Роль учителя выдаётся совпадением с переменной окружения, не одноразовым кодом. `app/bot/service.py:132–136`. Пока переменная пустая, в кабинет входит только демо-учитель из seed.
3. Ссылка `https://max.ru/<бот>?start=<ключ>` не читается. У `bot_started` поле `payload` выбрасывается (`app/bot/updates.py:29–40`). Текст `/start КЛЮЧ` не считается стартом: сравнивается точное `/start` или `start` (`app/bot/updates.py:70–71`), дальше ключ уходит в определение темы.
4. Соединение с внешней PostgreSQL при `ssl=require` шифруется без проверки сертификата: `CERT_NONE` и `check_hostname = False`. `app/db/session.py:33–38`. Боевой `DATABASE_URL` как раз с `ssl=require` (`docs/TIMEWEB.md`).
5. Секрет сессии по умолчанию `change-me`. `app/core/config.py:27`. Если на приложении забыть `SESSION_SECRET`, cookie можно подделать. На Timeweb переменная задана, риск в значении по умолчанию.
6. Демо-просмотр `?preview=teacher` и `?preview=student` открывается без `DEV` и без входа. Данные нарисованные, баннер это говорит, API не вызывается. `app/web/js/app.js:147–149`. ТЗ пускает мок только при `DEV=true`.

### Доставка и гонки

7. Вебхук обрабатывает апдейт до ответа, в том же запросе. `app/bot/routes.py:31–43`. LLM имеет таймаут 15 с (`app/llm/explainer.py:56`). Ответ на callback уходит после этой работы (`app/bot/service.py:118–119`), кнопка может висеть. Очереди `jobs` нет.
8. Маркер long polling пишется до разбора апдейтов. `app/bot/poll.py:34–37`. Ошибка обработки выкидывает событие навсегда.
9. Дедуп: сначала чтение, потом вставка. `app/bot/service.py:55–61`. Уникальный ключ есть, но второй параллельный запрос получит ошибку БД и вебхук ответит 500 (`app/bot/routes.py:40–43`). Если у сообщения нет `mid`, ключа нет и повтор не отсекается (`app/bot/updates.py:79–82`).
10. Отправка идёт до `commit`. Если MAX принял сообщение, а запись сессии не сохранилась, повторная доставка отправит ответ ещё раз. `app/bot/service.py:120`, `app/bot/routes.py:39`.
11. 429 и прочие ответы API не повторяются: логируется код и бросается исключение. `app/max_client/client.py:108–112`. Один общий `Lock` сериализует вызовы, отдельной очереди на 30 запросов в секунду нет.
12. Текст длиннее 4000 режется по символам, не по границе предложения. Кнопки остаются у последнего куска. `app/max_client/client.py:115–118`.
13. `bot_stopped`, `dialog_removed` и ошибка отправки «пользователь недоступен» не помечаются. Следующие отправки снова падают. Разбор апдейтов знает только `bot_started`, `message_callback`, `message_created` (`app/bot/updates.py:18–26`).
14. Группа и канал не отфильтрованы: `chat_type` в разборе не читается. Сообщение из чата, где бота не звали, обрабатывается как личное (`app/bot/updates.py:61–89`).
15. Миграции стартуют в фоне вместе с uvicorn. После 15 неудач скрипт выходит с кодом 0. `docker/entrypoint.sh:4–22`. API может принять трафик на пустой или старой схеме.
16. В `compose.yaml` нет `restart: always` и сервиса воркера. Для Timeweb это описание локального стенда, не боя.

### Зачёт, тема, диалог

17. «Площадь квадрата» и «сторона квадрата» попадают в квадратные уравнения: подстрока `квадрат` проверяется раньше геометрии. `app/domain/curriculum.py:135–138`. Нормализации `ё/е` нет. При неуверенности бот показывает все четыре темы, а не вопрос «это про геометрию?».
18. «Ещё задание» крутит два фиксированных пункта: `task_index % len(tasks)`. `app/domain/training.py:166` и банк в `app/domain/curriculum.py:36–47` (так же у остальных тем). Случайных параметров нет, уровней сложности нет.
19. Пока задание открыто, любой текст считается ответом. `app/domain/training.py:106–107` и `_grade` на строках 174–178. «Не знаю», «?», «подскажи» становятся неверной попыткой. Вопрос с «?» не переспрашивается.
20. `/start` посреди задания не сбрасывает шаг. `app/domain/training.py:96–97`. Следующее сообщение проверяется как ответ на старое задание.
21. Кнопки «Подсказка», «Пропустить», «Другая тема» под открытым заданием не выдаются. После одной проверки шаг становится `done` (`app/domain/training.py:188`). Лесенки из трёх попыток нет.
22. Допуск 0,001 применяется всегда, не только к десятичной записи ученика. `app/domain/answers.py:11–14`. Из-за этого `5` и `5.001` считаются одним ответом. Парсер не понимает юникодный минус `−`, «½», «10 см», «D=5», «x1=2; x2=3», «2 и 3», завершающую точку. Считается через `Decimal`, не через `fractions.Fraction`. `eval` нет — это правильно.
23. Статус считается по всем попыткам темы, не по последним 10. `app/domain/status.py:28–45`, выборка `app/bot/service.py:271–277`. Одна ошибка даёт «повторить» (доля 0). Верный ответ сразу после предыдущего верного уже считается повторной проверкой: паузы 12 часов нет (`app/domain/status.py:23–25`). Подсказка не даёт вес 0,5. Статуса «начато» нет. Это совпадает со старым планом и с `tests/test_domain.py:28–36`. Менять только после решения команды, иначе тесты и кабинет разъедутся.
24. Карта класса ключует ячейки именем, не id. Два одинаковых имени в одном классе перезапишут друг друга. `app/bot/service.py:424–431`.
25. Часовой пояс один на всё приложение, сейчас `Asia/Vladivostok`. `app/core/config.py:33`. Поля у класса нет. Серия считается в этом поясе (`app/bot/service.py:347–357`).

### Модель, фото, кабинет

26. Объяснение темы от модели подменяет текст без проверки на markdown, слова «ИИ» и эталон. Обрезается до 800 знаков. `app/bot/service.py:250–255`. Для разбора ошибки эталон отсекается (`app/bot/service.py:259`). Ретрая и дневного лимита нет (`app/llm/explainer.py:51–75`). Имя модели по умолчанию `qwen2.5` (`app/core/config.py:30`): локального Qwen в репозитории нет, но имя подталкивает поставить его на VPS.
27. Упоминания самоповреждения не выделены. Такой текст не попадёт в тему и получит обычное «выбери тему». Номера 8-800-2000-122 в коде нет.
28. Фото из MAX не скачивается. В сессию пишутся token и url, срок ставится, файл не лежит в хранилище. `app/bot/service.py:72–75`. Просрочка обнуляет поля только когда сессию снова открыли (`app/bot/service.py:209–218`). В мини-приложении байты читаются и тут же выбрасываются (`app/api/student.py:130–139`). Лимит 8 МБ, не 10. Текст вопроса в API ограничен 1000 знаками (`app/api/student.py:20`), не 4000.
29. Правки формулировок в предпросмотре на сервер не уходят. Отправка собирает черновик заново из банка и отвечает 501. `app/web/js/teacher.js:501–511` и `app/api/teacher.py:110–118`.

## 9. Порядок работ

Жду подтверждение этого порядка и таблицы D1–D8. До ответа код не меняю.

Каждый следующий этап — один коммит, со тестами и коротким отчётом. Уже написанное не переписывать целиком.

1. **Фундамент доставки.** Баги 7–16 и 3 (секрет уже есть). Таблица `jobs`, ответ 200 до LLM, воркер, ретрай 429, нарезка по предложениям, маркер polling после успеха, `bot_stopped`, игнор группы, `MAX_API_BASE`, проверка сертификата базы, миграции до приёма трафика, `docs/DEPLOY.md` под Timeweb App Platform (откат деплоя и восстановление базы). `/health` не переименовывать.
2. **Класс и доступ.** Баги 1–3. Не сажать в 8Б без ключа. Одноразовый код учителя. Ссылка `?start=`. Изоляция классов. Согласие при первом запуске вынести сюда, не оставлять на конец: в пилоте несовершеннолетние. Текст политики — заглушка и TODO, как в ТЗ.
3. **Диалог и задания вместе с тоном.** Баги 17–22, 30–31. Новые реплики сразу в `messages_ru.py`. Правила статуса (D2, D3) — отдельным коммитом в `status_rules.py`, чтобы не смешать с генератором. Блокировка на пользователя и версия кнопки входят сюда.
4. **LLM.** После шаблонов, чтобы числа считал код. Провайдер с хранением в РФ — выбор команды, в репозиторий ключ не класть. Пока URL пустой, остаются тексты из кода.
5. **Фото и OCR.** Скачивание, EXIF, закрытое хранилище, TTL, подтверждение «правильно прочитал?».
6. **Мини-приложение.** Поджать под D4: прогресс, пустые состояния, возврат в чат. `ready()` не добавлять (D7).
7. **Кабинет: сдача, викторина, отправка, материалы.** Только когда путь в чате уже живой. Имена на карте — по D1.
8. **Демо и ручной чек-лист.** `seed_demo.py` на ~20 учеников, `docs/QA.md`. Тесты на парсер, «площадь квадрата», статусы и вебхук добавлять в том этапе, который это меняет, а не копить до конца.

Выгрузку и удаление данных пользователя сделать в этапе 2 рядом с согласием. Ежедневный бэкап — это настройка базы Timeweb, её описать в `docs/DEPLOY.md`, не в коде приложения.

## 10. Как проверить текущий прототип руками

Локально, без боевого вебхука:

```bash
pip install -e ".[dev]"
pytest
python -m app.bot.poll
```

`pytest` нужен в виртуальном окружении: системный Python его не видит. Long polling и вебхук одного и того же бота вместе не работают. Туннель на `ideya_fiks_101_bot` не поднимать: у приложения `279257` уже задан `MAX_WEBHOOK_URL`.

Кабинет на `stimyl.online` открывается из MAX. Без `initData` будет экран входа. `?preview=teacher` показывает вымышленный класс и помечает его баннером.

## 11. Риски, если идти дальше без решений

- Публичный бот уже может записать постороннего в 8Б и показать его учителю.
- Включение LLM на вебхуке удлиняет ответ. Повторная доставка после сбоя даст второе сообщение, пока нет очереди и дедупа «ответ уже ушёл».
- Смена правил статуса без отдельного решения сломает `tests/test_domain.py` и текущую карту, которую команда уже видела на старом плане.
- Второй процесс с тем же `MAX_WEBHOOK_URL` перехватит подписку `ideya_fiks_101_bot`. Сейчас вебхук только у приложения `279257` (`docs/TIMEWEB.md`). Приложения `277859` больше нет.
